# 2027届产品岗监控：指定43家公司

公司名单来自金山表格：https://www.kdocs.cn/l/cn8UCcWyH6Hv

2026-11-02起仅监控用户指定的[43家公司](MONITOR_SCOPE.md)。实际每日采集和通知范围由`config/campus_product.json`的source_ids及companies同时限定。

`config/company_watchlist.json`保留原163家官网目录及适配记录，供历史追溯；保留目录不代表仍在每日采集。公开配置不包含个人投递进度、备注或飞书凭证。

- 每天北京时间09:00、15:00触发检查。GitHub Actions可能排队，实际提醒在检查完成后发送。
- 每个时段在10、20分钟后安排补偿触发；该时段已成功完成时直接跳过。失败发送不记为完成，补偿时继续重试。
- 排队的补偿任务从main读取最新已推和完成记录，避免使用排队前的旧快照重复发送。
- 本机另设09:35、15:35漏跑检查：已完成或正在运行时不重复触发，漏跑时才启动同一个云端工作流。此层需要电脑开机、Codex应用运行且Edge的GitHub登录有效；不替代云端计划，也不另发岗位通知。
- 仅提醒新增、官网明确适用于2027届、标题与产品有关的正式校招职位。
- 产品经理、产品策划、产品助理、产品运营以及Product类职位均可进入产品筛选；
  正文偶然提及产品经理的算法、开发、数据分析等非产品职位不提醒。
- 只运行这43家对应信源；现有专用API和公开官网/官方ATS适配继续使用，范围外信源不在每日任务中调用。
- 只有成功读到职位列表或明确空列表才能建立基线。登录墙、安全验证、超时、
  未找到真实职位列表或产品详情链接、未完成分页均列为异常/待适配，不能称为没有新增。
- 新公司的首次成功快照仅建立基线，避免把现有职位全推一遍。
- 已发送岗位按稳定官网ID或链接去重；飞书确认成功后才标记已发送，失败下次重试。
- `data/company_monitor_coverage.json`记录本轮真正读取成功与异常的公司数量；
  `data/official_board_snapshot.json`保留各公司的公开抓取结果；每轮Actions附件也包含这些文件。
- 新增公司加入清单不等于该官网已验证可抓取。应查看首次完整运行的覆盖报告，
  对异常网站逐家维护入口或专用适配器。代码不绕过登录、验证码或访问控制。

当前范围固定为用户指定43家公司；未来表格新增公司不会自动加入。范围外历史岗位、已发送记录与基线保留；它们不会进入提醒或本轮覆盖报告。
现有Feishu webhook和签名密钥继续由Actions Secrets注入，配置文件不保存密钥。

2026-11-01发现GitHub未产生当天09:00和15:00的自动运行事件，已人工补跑并重新启用工作流。新计划的真实自动触发尚待验证，不能凭定时配置或手动成功就认定准点运行已恢复。

不注入通知凭证，不修改岗位库或已推记录；是否真正进入日常提醒，以主工作流覆盖报告为准。
